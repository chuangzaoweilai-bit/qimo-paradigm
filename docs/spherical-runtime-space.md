# 球形运行空间设计

## 定位

球形运行空间是起末范式在底层运行环境上的一种工程化设计。

它不是传统重型虚拟机，也不是传统独立虚拟磁盘方案，而是一种以本地真实物理磁盘为底层依托、以柔性隔离空间为运行边界、以内嵌规则和质检实现闭环的底层运行空间构想。

这个设计曾作为专利方向考虑，现选择免费公开，作为起末范式公开体系的一部分。

## 一、核心底层基石

球形运行空间摒弃传统重型虚拟机和独立虚拟磁盘结构。

它以本地真实物理磁盘作为唯一底层依托：

```text
不强制重新分区
不割裂原有硬盘
不把运行空间建立在重型虚拟磁盘之上
不把原有数据区和虚拟空间粗暴切开
```

底层镜像保持极简空白，只保留虚拟空间核心运行内核。

该核心运行内核应常驻运行，用来维持空间规则、资源边界、隔离策略和闭环状态。

## 二、核心隔离逻辑：手套模型

球形运行空间采用“手套”式柔性隔离模型。

物理硬件是本体。

球形虚拟空间像套在本体外部的手套：

```text
直连物理磁盘
不破坏原有磁盘结构
不占用已用数据区
只从空闲空间中按需划拨
对外形成隔离运行空间
```

也就是说，球形空间不是把整块硬盘重新切开，而是在整机空闲存储空间中，按照规则动态划拨指定容量。

例如：

```text
从当前空闲空间中划拨 4TB
自动隔离锁定
不覆盖已用数据
不破坏原盘符和目录结构
```

## 三、资源自主定制能力

球形运行空间允许用户自主精细化限制硬件资源。

```text
磁盘：按空闲空间比例或固定容量分配
内存：按需设置上限
CPU：按需设置配额
```

目标是避免资源浪费、抢占和不可控扩张。

资源不是无限开放，而是进入结构化配置：

```text
资源起点
资源上限
分配规则
运行监控
越界处理
闭环验证
```

## 四、单路径极简运行机制

传统虚拟化系统往往包含多层路径、多层挂载、多层校验和多层映射。

球形运行空间追求单路径直连：

```text
物理磁盘路径 -> 球形空间映射路径 -> 程序运行路径
```

运行空间只保留一条主要路径。

这样可以减少路径嵌套、挂载冲突、路径漂移和多层校验带来的报错。

在起末范式中，这体现为：

```text
路径越少，闭环越清晰。
映射越直接，质检越明确。
```

## 五、全系统原生兼容

球形运行空间需要自动映射当前设备已有的系统结构。

例如在 Windows 中：

```text
A:
B:
C:
D:
```

在 Linux 中：

```text
/
/home
/mnt
/var
/opt
```

如果目标文件或目录不存在，系统应根据当前环境即时自适应生成。

这使命令行操作更轻量，也使空间在不同设备之间具有更高适配性。

## 六、安全加密闭环设计

球形空间只保留唯一进出入口。

不设计隐藏旁路。

入口应搭载端到端私有云加密通道，用来处理：

```text
访问
快照
备份
跨设备同步
配置同步
镜像拉取
```

安全目标是减少暴露面：

```text
唯一入口
端到端加密
最小可见端口
无隐藏旁路
所有传输走加密通道
```

公开设计中不把安全性表达为绝对不可破解，而是表达为最小暴露面和闭环式安全边界。

## 七、跨设备漫游能力

球形运行空间的规则、资源配置和隔离策略可以一次性预设并固化在镜像中。

当用户在另一台设备登录私有云后，可以拉取自己的专属镜像。

新设备启动后自动识别：

```text
本地物理磁盘
剩余空间
已有盘符或目录结构
可分配资源
可用 CPU 和内存
```

然后沿用原有规则自动部署。

目标是：

```text
环境随身带走
规则不丢失
资源边界不漂移
隔离策略不重写
```

## 八、双模式使用形态

球形运行空间分为两种使用形态。

### 通用版

面向普通用户。

```text
标准预设配置
开箱即用
无需理解底层隔离细节
自动完成资源划拨和空间映射
```

### 专业版

面向工程师和高级用户。

```text
开放规则自定义
可修改隔离策略
可调整权限
可配置资源参数
可扩展运行空间结构
```

## 与起末范式的关系

球形运行空间不是独立于起末范式的普通虚拟化方案。

它体现了起末范式的几个关键原则：

```text
末端先定：运行空间必须形成可验证隔离状态
单路径达末：减少多层路径导致的结构漂移
规则内嵌：资源、权限、隔离和同步规则固化在空间结构中
非静默处理：路径、资源、同步、加密失败必须显式记录
子结构闭环：磁盘、内存、CPU、入口、同步、镜像各自闭环
整体闭环：任一子结构未闭环，空间不能被判定为可用
```

## 核心定义

球形运行空间是一种以真实物理磁盘为底层依托、以柔性球形隔离为运行边界、以单路径映射和加密入口为核心、可跨设备漫游的底层运行空间设计。

它的目标不是复制传统虚拟机，而是为起末范式提供更轻、更直接、更闭环的底层运行环境。
