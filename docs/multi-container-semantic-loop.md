# 多容器语义训练闭环

## 背景

在构建区块链语义时，如果公开语料本身是碎片化的，系统就不能直接假设存在一个完整、专业、可用的区块链语义库。

这时需要从零构建训练逻辑、推理逻辑和闭环结构。

起末范式下的语义训练不是简单抓取语料再喂给模型，而是围绕领域末端生成阶段任务、训练语料、推理语义，并把结果重新纳入闭环。

## 起末定义

这个实验的起末结构是：

```text
起：我要获得完整的区块链语义
末：我一定会获得完整的区块链语义
中间：三容器语义训练闭环
```

这里的“完整区块链语义”不是泛泛的区块链介绍文本，而是由链上智能合约、阶段任务、训练语料、推理语义条目和反向核对共同构成的闭环语义结构。

## 三容器结构

早期实验可以抽象为三个容器：

```text
容器 1：阶段任务生成
容器 2：阶段语料训练
容器 3：语义推理生成
```

### 容器 1：阶段任务生成容器

负责生成区块链领域的阶段性任务清单。

它不直接训练，也不直接推理，而是把领域拆成可以推进的阶段任务。

在更精确的闭环中，容器 1 的任务来源不是随意编写的区块链目录，而是拉取链上智能合约，并从这些智能合约中生成阶段性任务清单。

容器 1 还有第二个职责：读取容器 3 生成的语义条目，核对自己生成的任务清单是否被正确执行。

因此容器 1 同时是：

```text
任务生成器
任务核对器
闭环守护器
```

在实际实现中，容器 1 还会维护 `state.json`，周期性检查 `tasks_index.json` 与 `semantic_entries.json`。

如果任务索引为空但合约可见，它会尝试重新生成任务清单。

如果语义条目未生成，它会进入 `waiting`，而不是伪装闭环成功。

示例：

```text
区块链基础概念
账户与地址
交易结构
区块结构
共识机制
智能合约
链上数据
跨链
安全风险
```

更贴近实验结构的任务来源：

```text
链上智能合约 -> 合约结构分析 -> 阶段性任务清单
```

### 容器 2：阶段语料训练容器

负责读取容器 1 生成的任务清单，并围绕每个阶段生成或训练语料。

它的目标不是堆积碎片文本，而是让每个阶段都能形成可被推理的专业语料结构。

容器 2 有严格门控条件：

```text
只有读取到容器 1 生成的任务清单，容器 2 才允许开始训练生成语料。
```

如果没有任务清单，容器 2 不应自行训练。否则训练语料会脱离起末结构，重新变成碎片化语料。

容器 2 的核心输出可以整理为 `corpus_entry`：

```text
task_id
type_id
file
contracts_count
stages
healthcheck
models
past
present.metrics
present.actions
present.security_notes
present.risk_prefilter
reasoning_input
reasoning_output
timestamp
```

其中 `healthcheck`、`past` 和 `present.actions` 让容器 2 的规则和质检进入结构本体；`reasoning_output` 必须显式记录当前是否达成。如果结果是“未达成”，它会成为容器 1 反向核对和生成修正任务的依据。

另一种结果聚合结构会把编译、部署、风险和多重验证放进 `results`：

```text
results.compile_result
results.deploy_result
results.risk_prefilter
results.interactions_digest
results.present_metrics
results.security_notes
results.actions
results.multi_verification
```

其中 `multi_verification` 用来处理复合状态。例如“编译成功但部署失败”不能被当作整体成功，而必须生成新的验证逻辑；“部署失败且高风险”不能被跳过，而必须生成新的探索路径。

示例：

```text
读取任务：交易结构
生成语料：
  - 交易是什么
  - 交易由哪些字段构成
  - 交易如何被签名
  - 交易如何被验证
  - 错误交易有哪些
  - 哪些交易路径必须被拒绝
```

### 容器 3：语义推理生成容器

负责读取容器 2 生成的语料，并进行推理，形成区块链语义。

它不只是总结语料，而是把语料推理成结构化语义：

```text
对象
场景
路径
约束
错误
禁止项
验证条件
末端状态
```

容器 3 也有严格门控条件：

```text
只有读取到容器 2 生成的语料，容器 3 才允许训练推理并生成完整语义条目。
```

如果没有语料，容器 3 不应凭空推理。否则生成结果无法被容器 1 核对，也无法证明语义闭环成立。

容器 3 的核心输出是 `semantic_entry`：

```text
unit_id
contract_name
source_file
task_id
phase
type_id
content
timestamp
trace
```

其中 `task_id` 是回连容器 1 的关键字段。容器 1 必须能通过 `semantic_entry.task_id` 核对原始任务是否被正确执行。

## 闭环关系

三个容器不是线性流水线，而是带门控与反向核对的闭环结构：

```text
链上智能合约
  -> 容器 1 生成阶段任务清单
  -> 容器 2 读取任务清单并训练生成语料
  -> 容器 3 读取语料并推理生成完整语义条目
  -> 容器 1 读取语义条目并核对任务清单是否正确执行
  -> 发现缺口或错误
  -> 生成新任务清单
```

如果推理出的语义不完整，就回到任务生成阶段继续补齐。

这符合起末范式的基本结构：

```text
起：构建专业区块链语义
末：形成可推理、可验证、可闭环的区块链语义结构
中间：多容器阶段训练与推理闭环
```

更精确地说：

```text
起：我要获得完整的区块链语义
末：我一定会获得完整的区块链语义
闭环验证：容器 1 必须能读取容器 3 的语义条目，并核对任务清单是否被正确执行
```

## 门控规则

三容器闭环必须遵守以下门控规则：

```text
规则 1：容器 1 先拉取链上智能合约，生成阶段性任务清单。
规则 2：容器 2 只有读取到容器 1 的任务清单，才能训练生成语料。
规则 3：容器 3 只有读取到容器 2 的语料，才能训练推理生成语义条目。
规则 4：容器 1 必须读取容器 3 的语义条目，核对任务清单是否正确执行。
规则 5：如果核对失败，闭环未成立，容器 1 必须生成修正任务或补充任务。
```

这些门控规则保证系统不会跑偏：

- 容器 2 不会脱离任务清单乱训语料。
- 容器 3 不会脱离语料凭空生成语义。
- 容器 1 不会只生成任务而不验证执行结果。
- 最终语义条目必须反向证明任务清单被正确执行。

## 小结构闭环

三容器只是一个简单构建，但它已经体现真正的闭环。

每个容器不是一个普通功能模块，而是一个内嵌规则和质检的小结构。

```text
容器 1：
  规则：必须从链上智能合约生成任务清单
  质检：必须读取容器 3 的语义条目核对任务执行

容器 2：
  规则：只有读取到容器 1 的任务清单才能训练
  质检：生成的语料必须对应任务清单

容器 3：
  规则：只有读取到容器 2 的语料才能推理
  质检：生成的语义条目必须能被容器 1 核对
```

如果任何一个容器的小结构不能闭环，完整区块链语义这个整体结构就不能闭环。

这也是起末范式不依赖外部补丁的原因：规则和质检不是后加的，而是结构本身的一部分。

## 与普通语料训练的区别

| 维度 | 普通语料训练 | 多容器语义训练闭环 |
| --- | --- | --- |
| 语料来源 | 网上抓取、混合整理 | 由阶段任务驱动生成 |
| 结构 | 文本堆积 | 任务、语料、推理、验证闭环 |
| 执行条件 | 各步骤可松散运行 | 后一容器必须读取前一容器产物 |
| 核对方式 | 通常只看训练结果 | 容器 1 反向读取语义条目核对任务 |
| 错误路径 | 容易被忽略 | 必须记录并标记 |
| 推理目标 | 生成回答 | 生成完整语义 |
| 失败处理 | 重新训练或调参 | 回到缺口生成新任务 |

## 区块链语义示例

一个区块链语义单元不应只记录“交易是什么”，还应记录：

```text
对象：交易

场景：
  - 正常转账
  - 余额不足
  - 签名错误
  - 双花尝试
  - 手续费不足
  - 合约调用失败

路径：
  - 可验证交易路径
  - 被拒绝交易路径
  - 恶意交易路径
  - 失败后重试路径

约束：
  - 签名有效
  - 余额足够
  - nonce 正确
  - 共识规则允许
  - 不破坏链状态

末端：
  - 合法交易被链接受
  - 非法交易被拒绝
  - 链状态保持一致
```

这才是面向起末范式的专业语义，而不是碎片化的区块链介绍文本。

## 核心定义

多容器语义训练闭环是一种把领域拆成阶段任务、由任务生成语料、由语料推理语义、再由语义条目反向核对任务执行情况的结构。

它服务于起末范式的完整语义库建设。

它的关键不是“三个容器顺序运行”，而是：

```text
每个容器的执行都受前一阶段产物约束
最终语义条目必须回到任务生成端接受核对
核对失败则闭环失败
任意小结构不闭环，整体结构不闭环
```
