# 起末范式运行时草案

## 目标

起末范式运行时的目标不是执行传统意义上的程序，而是维护一个能够接收起点、生成达末路径、演化状态、判断末端并显化结果的计算环境。

## 暂定运行时结构

```text
起点输入 -> 语义解析 -> 末端建模 -> 达末路径生成 -> 状态场演化 -> 末端判定 -> 结果显化
```

在程序构建场景中，运行时必须先接收或生成末端结构。

如果末端结构没有被确定，系统不能进入真正的达末执行。

## 组成部分

### 恒等内核

负责保证底层数字和符号先保持自身。

在这个层级中：

```text
1 就是 1
1.2 就是 1.2
```

任何人类语义都不能直接覆盖数字和符号本体。

例如，`1` 不会自动代表真、启用、完成或允许。这样的意义必须在状态场或语义结构中被显式声明。

### 起点接收器

负责接收计算触发源。

可能的触发源包括：

- 人类输入
- 外部事件
- 时间条件
- 状态变化
- 系统内部目标

### 语义解析器

负责把起点转化为系统可以处理的语义单元。

它不只是做文本解析，也需要识别目标、约束、对象、关系和完成条件。

### 完整语义库

负责记录对象在多个场景下的路径、约束、失败和排除项。

例如“得到苹果”的完整语义不应只包含“购买苹果”，还应包含：

- 自己购买
- 他人代买
- 线上配送
- 家中已有
- 请求赠予
- 不可行路径
- 禁止路径
- 失败后的替代路径

禁止路径也需要记录，但只能作为排除项参与计算。

例如“抢一个苹果”可能让表面末端成立，但它破坏合法性和安全约束，因此必须被达末器排除。

### 语义训练闭环

负责在完整语义库不存在时，从领域目标中逐步生成语义。

一种早期结构是三容器组合：

```text
容器 1：拉取链上智能合约并生成阶段任务
容器 2：读取阶段任务并生成训练语料
容器 3：读取训练语料并推理语义条目
```

运行时需要允许推理结果反向影响任务生成：

```text
链上智能合约 -> 任务 -> 语料 -> 语义条目 -> 容器 1 核对 -> 缺口 -> 新任务
```

这样系统不依赖现成的完整语义库，也不只依赖网上碎片化语料。

该闭环必须具备门控条件：

- 容器 2 只有读取到容器 1 的任务清单才能训练。
- 容器 3 只有读取到容器 2 的语料才能推理。
- 容器 1 必须读取容器 3 的语义条目，核对任务清单是否正确执行。

### 状态场

负责保存系统当前的存在状态。

状态场至少应包含：

- 当前目标
- 已知对象
- 对象关系
- 约束条件
- 历史轨迹
- 待演化事项

### 演化器

负责推动状态变化。

它根据当前状态、语义目标、约束和反馈决定下一步变化，而不是简单按固定指令序列执行。

### 达末器

负责回答“如何让末端成立”。

例如：

```text
起：我想要一个苹果
末：我最终一定会得到一个苹果
```

达末器需要把这个闭环拆成可推进的状态演化：

```text
确认当前是否已有苹果
如果没有，寻找可获得苹果的路径
比较路径成本、时间、约束和成功率
排除违法、危险或破坏约束的路径
执行路径
验证是否已经得到苹果
如果失败，生成下一条路径
```

### 末端判定器

负责判断一次计算是否已经完成、暂停、失败或转化为新的起点。

末端判定器不能只判断流程是否结束，而必须判断最终状态是否等于最开始定义的末端结构。

如果实际结果偏离预定末端，即使程序已经执行完，也必须判定为闭环失败。

### 结构质检器

负责检查每个小结构是否闭环。

它不是传统意义上的外部测试脚本，而是运行时结构的一部分。

每个小结构都必须暴露：

```text
前置条件
规则
产物
质检条件
失败回流
```

如果某个小结构没有通过质检，整体结构不能被判定为闭环。

### 显化器

负责把末端状态转化为外部可见结果。

显化形式可以是：

- 文本
- 文件
- 命令
- 界面变化
- 状态记录
- 新的起点

## 最小运行循环

```text
while system_is_active:
    origin = receive_origin()
    semantic_unit = parse(origin)
    terminal = model_terminal(semantic_unit)
    path = generate_path(state, terminal)
    state = evolve(state, path)
    if reached_terminal(state):
        manifest(state)
```

## 第一版实现目标

第一版 reference implementation 不需要完整证明整个范式，只需要证明：

1. 计算可以从语义起点进入系统。
2. 系统能够维护一个状态场。
3. 系统能够查询完整语义库，识别可行路径和禁止路径。
4. 系统能够在语义库不足时通过阶段任务生成训练闭环。
5. 系统能够根据末端生成达末路径。
6. 状态演化不是简单函数返回，而是有过程记录。
7. 系统能够检查小结构是否通过内嵌质检。
8. 末端判定可以识别“流程跑完但末端未成立”。
9. 末端判定可以决定结果如何显化。
