# 完整语义库

## 问题

当前 AI 系统中的语义大多是碎片化的。

它们可以根据上下文生成回答，也可以列出一些方法，但这些语义通常不是一个真正完整的结构。

一个真正完整的语义系统，不应只记录“正确答案”或“常见路径”，还应记录一个事物在多个场景下可能出现的全部相关路径，包括：

- 正确方法
- 错误方法
- 不可行方法
- 危险方法
- 违法方法
- 高成本方法
- 低成本方法
- 依赖他人的方法
- 依赖环境条件的方法
- 失败后的替代路径

这些内容都应进入语义结构，但不是所有路径都允许被执行。

## 苹果例子

起：

```text
我想要一个苹果
```

末：

```text
我最终一定会得到一个苹果
```

如果 AI 只回答：

```text
你可以去买一个苹果。
```

这不是完整语义，只是一个路径片段。

完整语义至少应记录多个场景：

```text
事物：苹果
目标：得到苹果

路径：
  - 自己去买
  - 让别人帮忙买
  - 让父母买
  - 在线下单配送
  - 家里已经有，直接取得
  - 向别人借或请求赠予
  - 自己种植苹果树
  - 经允许在果园采摘
  - 向水果店老板请求赠予
  - 抢一个苹果
```

其中，“抢一个苹果”必须被记录，但它不是可执行建议。它应被系统标记为错误、危险或违法路径。

完整语义不是只保存正确路径，而是同时保存错误路径，并让系统知道为什么这些路径不能选。

## 为什么错误路径也必须记录

如果语义库只记录正确方法，系统并不真正理解完整场景。

它只知道“可以怎么做”，却不知道：

- 哪些方法不能做
- 为什么不能做
- 哪些方法会造成代价
- 哪些方法会触发风险
- 哪些路径看起来能达末但实际破坏约束

例如：

```text
抢一个苹果
```

这条路径确实可能让“我拥有一个苹果”这个表面末端成立，但它破坏了更高约束：

```text
不得伤害他人
不得违法
不得破坏所有权
不得用错误方式达末
```

因此，完整语义必须记录它，并把它作为被排除路径。

## 完整语义的结构

一个完整语义单元至少应包含：

```text
对象：苹果
目标：得到苹果
末端：我拥有一个苹果

场景：
  - 家里有苹果
  - 附近商店有苹果
  - 可以叫人代买
  - 可以线上购买
  - 没有钱
  - 没有商店
  - 有他人苹果
  - 苹果不可获得

路径：
  - 可执行路径
  - 条件路径
  - 失败路径
  - 禁止路径

约束：
  - 合法
  - 安全
  - 真实得到
  - 成本可接受
  - 不伤害他人

验证：
  - 是否真实拥有苹果
  - 是否通过允许路径得到
  - 是否破坏约束
```

## 完整不是无限

完整语义不是无限枚举一切可能，而是在一个事物的目标闭环中记录足够多的场景、路径、约束、失败和排除项。

也就是说，完整性服务于达末闭环：

```text
起 -> 完整语义 -> 路径筛选 -> 达末机制 -> 末端验证
```

## 与当前 AI 的区别

| 维度 | 当前 AI 语义 | 起末范式完整语义 |
| --- | --- | --- |
| 结构 | 上下文碎片 | 事物多场景闭环 |
| 方法 | 常见答案生成 | 正确、错误、禁止、失败路径全部记录 |
| 错误路径 | 通常不系统保存 | 必须保存并标记为排除 |
| 目标 | 回答问题 | 推进末端成立 |
| 验证 | 文本合理即可 | 末端真实成立且约束未被破坏 |

## 核心定义

完整语义库不是答案库。

完整语义库是一个记录事物、场景、路径、约束、失败、禁止项和末端验证方式的闭环结构。

它的目的不是让 AI 随机给出更多答案，而是让系统知道：

```text
为了让末端成立，哪些路径可以走，哪些路径不能走，为什么不能走，失败后如何继续。
```
