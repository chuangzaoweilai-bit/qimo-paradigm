# 达末路径扩展

## 核心观点

“一定会得到”不是只依赖当前手里已有的资源。

在起末范式中，当前资源不足不会直接让末端失败，而是触发达末路径扩展。

例如：

```text
起：我想要一个苹果
末：我一定会得到一个苹果
```

如果我自己没有苹果、没有钱，系统不能立刻判定失败。它必须继续扩展路径：

```text
让父母买一个苹果给我
让朋友买一个苹果给我
去允许采摘的果园摘一个
向水果店老板请求赠予一个
寻找家中已有的苹果
寻找可交换、可赠予、可配送、可协助的路径
```

这些路径都属于完整语义的一部分。

## 资源不足不是终点

传统系统容易把资源不足看成失败：

```text
没有钱 -> 不能买 -> 失败
```

起末范式不会这样结束。

资源不足只是说明当前路径不能达末：

```text
自己购买路径失败 -> 扩展到他人协助路径
他人协助路径失败 -> 扩展到请求赠予路径
请求赠予路径失败 -> 扩展到合法采摘或生产路径
```

所以，“没有钱”不是末端失败，而是路径切换信号。

## 路径扩展层级

以苹果为例，达末路径可以分层：

```text
自身路径：
  - 自己购买
  - 家中已有
  - 自己种植

亲缘路径：
  - 父母购买后给我
  - 家人已有并给我

社交路径：
  - 朋友购买后给我
  - 朋友赠予

市场路径：
  - 水果店购买
  - 线上配送
  - 交换获得

请求路径：
  - 向店主请求赠予
  - 向他人说明需求并请求帮助

环境路径：
  - 经允许在果园采摘
  - 从开放采摘场景获得
```

路径越完整，系统越不容易把一个局部失败误判为整体失败。

## 允许路径与禁止路径

路径扩展不代表任何方式都能执行。

完整语义必须同时记录允许路径和禁止路径。

例如：

```text
允许路径：父母购买后给我
允许路径：朋友赠予
允许路径：店主自愿赠予
允许路径：经允许采摘

禁止路径：偷一个苹果
禁止路径：抢一个苹果
禁止路径：未经允许进入果园采摘
```

禁止路径要被记录，但只能作为排除项，不能作为达末执行路径。

## “一定”的严谨定义

起末范式中的“一定会得到”可以定义为：

```text
系统不能在单一路径失败后终止。
系统必须持续扩展允许路径。
系统必须验证末端是否真实成立。
系统不能把中间结果伪装成末端。
系统不能选择破坏约束的路径。
```

也就是说，“一定”不是盲目保证某条固定路径成功，而是保证系统围绕末端持续扩展、筛选、执行和验证，直到允许路径使末端成立。

如果某个阶段仍未成立，系统不能宣布失败完成，而必须进入缺口闭环：

```text
当前允许路径不足 -> 生成缺口 -> 扩展语义 -> 生成新路径 -> 继续达末
```

## 核心定义

达末路径扩展是起末范式保证末端成立的关键机制。

它让系统不被单一资源、单一方法或单一失败困住，而是不断从完整语义中寻找新的允许路径。
