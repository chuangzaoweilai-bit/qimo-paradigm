# 苹果例子

## 目标

用一个极小例子说明起末范式如何看待计算。

## 传统写法

用户输入：

```text
我想要一个苹果
```

传统系统可能会把它转换成一次搜索、一次推荐、一次购买链接返回，或者一次预设函数调用：

```text
search("apple nearby")
return links
```

## 起末范式写法

在起末范式中，这不是一次简单查询，而是一次从起到末的闭环计算。

### 起点

```text
我想要一个苹果
```

### 语义单元

```text
目标: 得到苹果
对象: 苹果
期望末端: 我拥有一个苹果
约束: 苹果必须真实存在，并且能被我取得
```

### 当前状态场

```text
我:
  has_apple: false

环境:
  nearby_store: unknown
  delivery_available: unknown
  money_available: unknown
```

### 达末过程

```text
1. 识别末端状态：我必须拥有一个苹果
2. 检查当前状态：我现在没有苹果
3. 查询完整语义：家中是否已有、附近是否可买、是否可配送、是否可向他人取得、哪些路径禁止
4. 排除路径：抢一个苹果等违法或危险路径不能执行
5. 扩展路径：父母购买、朋友购买、店主自愿赠予、经允许采摘、交换或配送
6. 选择路径：根据合法性、安全性、可行性、成本、时间和约束选择
7. 执行动作：购买、配送、领取、请求赠予或经允许采摘
8. 验证末端：我是否已经真实拥有苹果
9. 如果失败，重新生成路径并继续演化
```

### 末端

```text
我.has_apple == true
```

### 显化

```text
我得到了一个苹果
```

## 这个例子要表达的差异

传统系统重视“用户输入后执行了什么程序或返回了什么结果”。

起末范式重视“一个起点如何被系统推进到必然成立的末端”。

完整语义不是只列出正确方法，也要记录错误方法，并把错误方法作为排除项。

例如：

```text
抢一个苹果
```

这条路径可能让“我拥有苹果”的表面状态成立，但它破坏合法、安全和所有权约束，所以不能被达末机制执行。

也就是说，核心不是：

```text
输入 -> 程序 -> 输出
```

而是：

```text
起 -> 达末机制 -> 末
```
